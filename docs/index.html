Finding Content Pages Worth Refreshing

A practical machine learning approach to identifying content pages that may need attention, using search and engagement signals.

Abstract

This project looks at a simple question: can we use existing search and engagement data to identify content pages that are showing signs of decline? I built a classification model using signals such as impressions, clicks, search position, engagement and content age, while keeping the prediction target separate from information that would only be known later. On the honest validation split, the model achieved a Precision@50 of 0.680, compared with a test-set base rate of 0.517. This suggests that the model can do a better job than simply selecting pages at random, although the result should not be treated as proof that refreshing a page will improve its performance. The main goal is therefore to give a content team a useful ranked starting point for human review rather than automatically deciding which pages should be changed.

1. The Question

Content teams usually have more pages than they have time to review. The question I wanted to investigate was whether the data already available for those pages could help narrow down where the team should look first.

Research question: Can search performance, engagement and content-age signals be used to rank pages that are more likely to show signs of decline?

This is a ranking problem rather than an attempt to completely automate content decisions. A useful model should help a person decide where to spend their time first.

2. Data

The analysis uses the FlyRank ML Internship dataset. The working dataset contains 30,000 content pages, with one row representing one content page.

The available fields include search demand, competition, content characteristics, search performance and engagement signals. The analysis uses public-safe and anonymized information only. Client names, private search queries and other identifying information are not included in the paper.

Time windows

The main performance signals are based on 90-day and 30-day windows. The 30-day fields also provide a previous-period comparison, which makes it possible to measure whether recent performance has moved relative to the preceding period.

Unit of analysis

One row represents one content page. The dataset contains 30,000 unique content IDs and no duplicate content-ID rows.

3. Methodology

Features

I used signals that would reasonably exist when making a content review decision. These included impressions, clicks, CTR, average search position, engagement rate, content age and recent performance changes. Categorical information such as content type and intent was also considered where appropriate.

Label

The target is a binary indicator for whether a page is classified as declining. The label is based on the defined trend direction rather than being manually assigned after looking at the model's prediction.

Baseline

I compared the model against a simple baseline. This matters because a model is only useful if it improves on a straightforward rule. Precision@50 was used as the main ranking metric because the practical question is which pages should be reviewed first.

Validation

I also tested the model using an honest validation split rather than relying only on the original result. The final honest-split result was a Precision@50 of 0.680.

Leakage checks

A major part of the analysis was checking that the model was not accidentally using information derived from the target or information that would only become available after the prediction point. Future performance windows and target-derived fields were treated as leakage risks and excluded from the final feature set.

4. Results

The final model was evaluated on an honest validation split using Precision@50. The idea here is pretty simple: if the team only has time to look at a small number of pages, are the pages at the top of the model's list actually more likely to be declining?

What I take from the results: The model looks useful as a prioritisation tool. It improves on the baseline on the same metric and gives the content team a smaller group of pages to investigate first. It does not tell us that a particular page definitely needs a refresh, or that a refresh will cause better performance.

5. Limitations

There are several reasons not to overstate these results. First, this is observational data, so the model can identify patterns and associations but cannot prove that one factor caused a page to decline.

Second, Precision@50 only tells us about the quality of the highest ranked pages. It does not mean that every page outside the top 50 is unimportant.

Finally, a page being identified as declining does not automatically mean that refreshing it is the correct solution. Search demand, competition, seasonality, content quality and other factors can all affect performance.

Honest interpretation: The model should be used to prioritise human review, not to automatically decide which content should be changed.

6. Ranked Recommendations

Based on the analysis, I would use the model as a first-pass queue for a content team.

1. Start with the highest-ranked pages Review the top of the model's queue first because these pages have the strongest combination of signals associated with decline.
2. Check the reason before changing anything A ranking is a starting point, not a diagnosis. The reviewer should look at the page, its search position, traffic trend and intent before deciding what action makes sense.
3. Prioritise pages where the decline is meaningful A small movement in traffic does not necessarily justify a content refresh. Larger or more consistent changes deserve more attention.
4. Keep a human in the loop The model should recommend what to inspect first. The final decision about rewriting, updating, merging or leaving a page alone should remain with a person.
5. Recheck the model over time Search behaviour changes, so a ranking system should not be assumed to stay accurate forever. Its performance should be monitored and the model reconsidered when the underlying data changes.
